# Observability — journald → Alloy → Loki → GCS

One pipeline, no agents on the application: everything the app and the host say goes
through the systemd journal, gets parsed and shipped by Grafana Alloy, lands in a
single-binary Loki backed by a GCS bucket, and is queried from Grafana Cloud over
mutual TLS. Configs live in [`deployment/loki/`](../../deployment/loki/) and deploy via
the `10-monitoring` Ansible role.

```mermaid
flowchart LR
    APP[Spring Boot\n(journald via systemd)] --> J[(journald)]
    K[kernel audit] --> J
    SSH[sshd] --> J
    J --> A[Grafana Alloy v1.4.3\n4 parser pipelines · client-side WAL]
    A -->|push, mTLS| NG[nginx loki vhost\nCN allowlist]
    NG --> L[Loki 3.5.3\nTSDB v13 · ingester WAL]
    L --> GCS[(GCS bucket\n720h retention, compactor-enforced)]
    G[Grafana Cloud\nclient certificate] -->|query, mTLS| NG
```

## The four parser pipelines (Alloy)

| Pipeline | What it extracts |
|---|---|
| Spring Boot | Multiline reassembly, then `trace_id` / `span_id` / `exception_class` labels — logs correlate with the app's MDC request ids |
| systemd/sshd | `alloy_ssh_failed_attempts_total` — the **security-activity signal** (it fired throughout the pentest waves) |
| kernel | Audit syscall record decoding |
| generic | Everything else, labeled by unit |

## Access control: mTLS instead of rate limits

The `loki.checkitout.app` vhost enforces `ssl_verify_client on` against a private CA;
only certificates with CN `alloy@CheckItOut` (push) and `grafana-cloud@CheckItOut`
(query) pass the auth_request gate. nginx rate limiting is deliberately **off** on
this vhost — possession of a client certificate *is* the access control. Certificates
are generated by the monitoring role (note the documented container-UID 10001 vs
host-UID 995 permission gotcha if you touch volumes).

## Retention & durability

Loki runs single-binary with TSDB v13 on a GCS bucket, ingester WAL for crash
durability, and compactor-enforced **720 h (30-day) retention** — the window is tied
explicitly to the platform's ToS/data-retention commitments, not left to defaults.

## Application-side metrics

`application-actuator.yml` / `application-monitoring.yml` gate the actuator surface
(public: `/health` only; everything else ADMIN), define readiness/liveness health
groups, export Prometheus metrics (upload subsystem ships its own `uploads_*` series
with a committed Grafana dashboard JSON), and declare webhook-backed alert thresholds.

## Honest notes

- The collector is **Grafana Alloy** — `PRODUCTION-LOGGING-ARCHITECTURE.md` still
  describes the earlier Promtail design in places; the Alloy config
  (`deployment/loki/alloy-config.alloy`) is the source of truth.
- Alloy's client-side WAL runs under its experimental stability flag — a deliberate
  trade for delivery guarantees.
- Grafana itself is external (Grafana Cloud with a client certificate); there is no
  self-hosted Grafana in this repo.
